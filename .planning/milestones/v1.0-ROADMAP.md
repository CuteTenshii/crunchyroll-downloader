# Milestone v1.0: Improvement & Optimization Pass

**Status:** ✅ SHIPPED 2026-07-10
**Phases:** 1-5
**Total Plans:** 18

## Overview

Performance, usability, UX, and code quality improvements to the Crunchyroll downloader. 5 phases targeting the highest-impact pain points: memory usage, error handling, configuration ergonomics, progress output, and test coverage.

## Phases

### Phase 1: Foundation — Error Handling, HTTP, Memory

**Goal:** Eliminate crashes, reduce RAM, and fix the most dangerous bugs in the download pipeline.
**Depends on:** None
**Plans:** 5 plans (01-01 through 01-05)

Plans:
- [x] 01-01: Foundation error handling — replace panic() with error returns, season continuation, mux cleanup warnings
- [x] 01-02: HTTP client context and retry — configured transport, timeouts, context propagation, bounded 401 refresh
- [x] 01-03: Streaming segment assembly — disk-backed encrypted temp files, configurable workers
- [x] 01-04: Widevine device discovery — sync.Once cache, explicit env/.env paths, deterministic precedence
- [x] 01-05: Interruption cleanup — SIGINT/SIGTERM handling, ffmpeg termination, local artifact cleanup

**Details:**
- 1.1 touches every internal package — most invasive change, unblocks everything else
- 1.2 is the highest-impact performance fix (400MB → ~64KB per-episode RAM)
- 1.6 is intentionally last so tests can validate refactored code
- 1.7 and 1.8 are low-effort fixes catching resource leaks and signal safety gaps

### Phase 2: Performance — Caching & Parallelism

**Goal:** Optimize multi-dub downloads and eliminate redundant work.
**Depends on:** Phase 1
**Plans:** 3 plans (02-01 through 02-03)

Plans:
- [x] 02-01: MPD manifest cache — sync.RWMutex + map, wired into sequential audio loop
- [x] 02-02: Parallel audio version processing — errgroup fan-out, fail-fast, deferred bulk cleanup
- [x] 02-03: GetBaseUrl split — GetVideoBaseUrl/GetAudioBaseUrl with explicit switch/case bandwidth matching

**Details:**
- Plans 2.1 and 2.3 are Wave 1 (independent, both modify manifest.go + episode.go)
- Plan 2.2 is Wave 2 (depends on 2.1 for MPD cache)
- 2.2 depends on Phase 1's error handling and cached Widevine device

### Phase 3: Usability — Configuration & Validation

**Goal:** Better CLI ergonomics — env vars, config files, validation.
**Depends on:** Phase 2
**Plans:** 5 plans (03-01 through 03-05)

Plans:

- [x] 03-03: FFmpeg startup check + --widevine-device flag with auto-detect
- [x] 03-04: Code quality fixes — regex sanitizeFilename, parseLangs once, URL validation fix
- [x] 03-05: CRUNCHYROLL_CLIENT_AUTH env var override for Basic Auth credential

### Phase 4: User Experience — Progress & Output

**Goal:** Human-friendly and machine-friendly output.
**Depends on:** Phase 3
**Plans:** 3 plans (04-01 through 04-03)

### Phase 5: Testing & Quality

**Goal:** Comprehensive test coverage and CI integration.

## Milestone Summary

**Key Decisions:**
- Return errors instead of panicking throughout the codebase
- Disk-backed encrypted segment assembly (400MB → ~64KB RAM per episode)
- Per-episode MPD manifest cache with sync.RWMutex
- errgroup fan-out for parallel audio version processing
- Pointer-field Config struct for explicit-only JSON overrides
- CLI flag > env var > config file > default precedence hierarchy
- Package-level output.Global singleton (mirrors config pattern)
- Table-driven tests using Go stdlib only (no testify)
- CI with continue-on-error for golangci-lint

**Issues Resolved:**
- 37/37 v1 requirements satisfied
- All panic() calls eliminated (zero matches in .go files)
- 224 KB+ lines of code modified across 151 files
- 125 commits since project inception

**Issues Deferred:**
- Strict 60% coverage target for internal/media, internal/download (Phase 5 achieved partial — media 52.7%, download 26.0%)
- QOL-15: Rate-limit handling with exponential backoff
- QOL-16: Disk space check before starting downloads

**Technical Debt Incurred:**
- 4 behavior_unverified items in Phase 1 (OS signal paths require human UAT)
- golangci-lint issues may exist (run with continue-on-error in CI)
