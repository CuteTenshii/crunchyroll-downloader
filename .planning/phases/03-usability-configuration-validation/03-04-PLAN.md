<behavior>
- `sanitizeFilename("a__b")` returns `"a_b"` (double underscore collapsed)
- `sanitizeFilename("a___b")` returns `"a_b"` (triple underscore collapsed)
- `sanitizeFilename("a_b")` returns `"a_b"` (single underscore unchanged)
- `sanitizeFilename("")` returns `"Unknown"` (empty input)
- `sanitizeFilename("a ")` returns `"a"` (trailing space trimmed)
- `sanitizeFilename("a:b")` returns `"a_b"` (illegal chars become underscore)
- `sanitizeFilename("a__:__b")` returns `"a_b"` (illegal chars + multi-underscore collapsed together)
</behavior>

3. Replace the `for strings.Contains(res, "__") { res = strings.ReplaceAll(res, "__", "_") }` loop (lines 30-32) with `res = multiUnderscore.ReplaceAllString(res, "_")`.
4. Keep everything else in sanitizeFilename unchanged (empty check, illegal chars loop, TrimRight).

Test in internal/download/episode_test.go:

Note: main.go's `validateURL()` was already added in Plan 3.2. The processURL function still uses the old string-split method. This task removes the old string-split approach and replaces it with `url.Parse()`.

Changes:

1. In `processURL`, replace the string-split URL parsing block (current lines 39-48):
   - Remove `parts := strings.Split(url, "/")` and the `len(parts) < 5` check.
   - Use `url.Parse(url)` to parse the URL. On error, print "Invalid URL: {err}" and return.

   - Split trimmed on `/` to get segments.
   - `contentType := segments[0]`, `contentID := segments[1]` (with bounds check for len).

2. Remove `"strings"` from imports if no longer needed (but `strings` is still used for `parseLangs` and other operations — check first, only remove if truly unused after changes).

Note: The `validateURL` function added in Plan 3.2 already uses `url.Parse()` and the correct `||` operator. The main concern in processURL is consistency — make it use the same parsing approach so the pre-validation (validateURL) matches the parsing in processURL.

The existing test `TestProcessURLRejectsInvalidContentIDLength` should still pass because processURL still rejects short IDs (now via `||` instead of `&&`). The existing `TestProcessURLRejectsUnsupportedContentType` should still pass.

Changes in main.go:

1. Change `processURL(ctx, client, url string)` signature to `processURL(ctx context.Context, client *api.Client, url string, audioLangs, subsLangs []string)`. Remove the parseLangs calls from inside processURL (current lines 55, 59).

5. main_test.go: Update the existing `processURL` test calls to pass empty lang slices (maintains test interface).
   - Line 14: `processURL(context.Background(), nil, "https://...")` → add `, nil, nil`.

Per D-22: parseLangs runs AFTER config/env resolution, so lang values benefit from full precedence chain.

The Episode() and Season() signatures don't change — they already accept `[]string` slices. This is a win: processURL was calling parseLangs every time it ran; now it's once per invocation.
