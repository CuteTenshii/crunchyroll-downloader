<action>
Modify main.go to add FFmpeg startup validation and wire --widevine-device:

1. Add `import "crunchyroll-downloader/internal/drm"` to imports.

2. Add `checkFFmpeg() error` function (unexported):
   - Call `exec.LookPath("ffmpeg")`. If error, return `fmt.Errorf("FFmpeg not found: install FFmpeg and ensure it is on $PATH. See https://ffmpeg.org/download.html")`.
   - Call `exec.Command("ffmpeg", "-version").Run()`. If error, return `fmt.Errorf("FFmpeg found at %s but failed to run: %w", path, err)`.
   - Per D-18 and RESEARCH.md code example lines 607-623.

3. In `main()`, after config resolution (Plan 3.1 changes) and before any API client creation:
   a. Call `if err := checkFFmpeg(); err != nil { fmt.Printf("Error: %v\n", err); os.Exit(1) }`.
   b. Resolve `resolvedWidevineDev` using precedence: `resolveString("widevine-device", *widevineDev, "WIDEVINE_DEVICE_PATH", cfg.WidevineDevice, "")`.
   c. If `resolvedWidevineDev != ""`, call `drm.SetWidevinePath(resolvedWidevineDev)`.
   - This MUST happen before `api.NewWithContext(ctx, resolvedEtpRt)` to ensure sync.Once in GetWidevineDevice uses the correct path (per Pitfall 3 in RESEARCH.md:468-472).

4. The `--widevine-device` flag is already defined from Plan 3.1.

The FFmpeg check runs after config loading (so config errors surface first) but before API client creation (so downloads don't start without FFmpeg). The SetWidevinePath call sits between FFmpeg check and API client creation.
</action>
