<objective>
Fix SpeedTracker.Bps() that incorrectly sets oldestTime to the newest sample timestamp, causing elapsed time to be near-zero and speed values to be unrealistically high (GB/s).
</objective>

<context>
The Bps() function iterates samples in reverse (newest first). On i==0, it sets oldestTime = st.buf[idx].at where idx is the newest sample. This means oldestTime is the most recent timestamp, causing `time.Since(oldestTime)` to be very small, and `totalBytes / tiny_elapsed` to produce astronomically large speeds (e.g. 129 GB/s).

The fix: track the minimum timestamp among valid (non-stale) samples instead of setting oldestTime at i==0.
</context>

<tasks>

<task type="auto">
  <name>Fix oldestTime in Bps()</name>
  <files>internal/output/speed.go</files>
  <action>
    In SpeedTracker.Bps(), remove the `if i == 0 { oldestTime = ... }` block. Instead, inside the `if st.buf[idx].at.After(cutoff)` block, track the minimum timestamp: set oldestTime when it's zero or when the current sample's timestamp is before oldestTime.
  </action>
