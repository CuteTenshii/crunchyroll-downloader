<objective>
Add .env file support to load CRUNCHYROLL_ETP_RT, WIDEVINE_CLIENT_ID_PATH, WIDEVINE_DEVICE_PATH, WIDEVINE_PRIVATE_KEY_PATH, XDG_CONFIG_HOME, and OUTPUT_DIR from a `.env` file in the working directory or parent directories.
</objective>

<context>
The codebase already supports these environment variables via os.LookupEnv() directly. However, there is no .env file loader — users must export vars manually or pass CLI flags. The .env support was previously removed in Phase 03 (D-15, D-16) but the user wants it back.

The precedence chain remains: CLI flag > env var > .env file > config file > default
</context>

<tasks>

<task type="auto">
  <name>Task 1: Create .env loader</name>
  <files>internal/config/dotenv.go</files>
  <action>
    Create internal/config/dotenv.go with a LoadDotenv function that:
    - Starts from the current working directory (os.Getwd)
    - Looks for `.env` files walking up to parent directories (like godotenv)
    - Parses KEY=VALUE lines, trimming whitespace and ignoring comments (#) and blank lines
    - Supports single and double quoted values
    - Calls os.Setenv for each parsed key=value
    - Returns the path of the loaded .env file (or empty string if none found)
    - Does NOT fail if no .env file exists — silently returns empty string

    Keep it lightweight — no external dependencies, ~50 lines.
  </action>
  <verify>go build ./internal/config/...</verify>
  <done>internal/config/dotenv.go compiles, LoadDotenv walks up directories and finds/loads a .env file</done>
</task>
